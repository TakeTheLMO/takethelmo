## 이번 점검에서 보완한 부분

1. 가입 화면의 시스템 관리자 선택, 예시 계정 주소 사칭, 허위 점검자 표시를 정리했다.
2. 종료·검토 중인 조치/사고 기록은 사용자 직접 변경을 막고, 신규 이력의 이름·시각을 서버가 확정한다.
3. 신규·교체 증빙과 검토 제출·종결에 쓰는 증빙은 본인 계정의 원본과 이름·유형·크기가 일치해야 한다. 원본이 없는 기존 자료의 제목 같은 단순 정정은 허용한다. 원본 없는 증빙을 새로 확인·종결하지 않으며, 재조치 요청 후 원본을 재첨부할 수 있다.
4. 관리자 점검 확인과 사용자 문의 초안 저장이 겹치는 상황에 독립 초안의 변경을 보존하도록 보강했다. 서버 응답이 늦는 동안 추가 입력한 내용도 보존한다. 충돌 사본은 이전 것을 덮어쓰지 않고 함께 다운로드하며, 공간 부족이면 입력을 유지한 채 자동 재시도를 멈춘다.
5. 관리자 포털의 미종결 조치·사고 수는 비관리자 사용자들의 등록 자료를 합산한다.

## 실제 운영 전에 남는 부분

- 기관 공식 서식 전체, 서명, 실제 IBC 접수·심의·LMO 신고, 교육 진위 확인, 담당자·처리 기간 연동은 미완성이다.
- 기관 공통 연구실 ID와 구성원별 접근 범위, 지정 책임자에게만 배정하는 확인 절차는 별도 설계가 필요하다. 현재 자료·월간 점검 범위는 계정별이다.
- 관리자가 게시할 자료가 없는 메뉴는 빈 상태/참고 안내를 표시한다. 같은 도메인의 메뉴는 공통 화면을 재사용하며 모든 메뉴가 각각 독립된 기관 업무 시스템인 것은 아니다.
- 초기 파일이 일부 남아 있는 예전 계정과 실제 운영 DB는 삭제·초기화하지 않았다. 새 테스트 자료는 별도 임시 DB에만 생성했다.

## Claude와의 검토

개인 `claude-debate` 스킬의 실제 Claude Code CLI를 사용했다. `opus`가 `claude-opus-5-5`로 확인되었고 `--effort xhigh`를 전달했다. 변경 전 코드와 요구사항으로 2회, 1차 수정 후 핵심 코드를 새로 동결한 자료 묶음으로 2회 의견을 교환했다. Claude에게 실제 DB·비밀번호 파일·원본 PPT 개인정보를 전달하지 않았다. 최종 교정 패치를 Claude가 다시 검토한 것은 아니며 테스트 실행과 최종 화면 확인은 Codex가 수행했다.

검토를 통해 저장 충돌 중 추가 입력 유실, 복구 사본 덮어쓰기, 점검 필드·이력 변조, 기존 증빙이 없는 자료의 정정 문제를 보완했다. 첨부가 없는 예전 자료는 단순 정정할 수 있게 하되 새로운 검토 완료에 증빙을 생략하는 예외는 두지 않기로 합의했다. 관리자 동시 수정은 읽은 상태의 정확한 버전을 트랜잭션에서 검사하며, 그 사이 사용자 수정이 발생하면 거부되는 테스트를 추가했다.
