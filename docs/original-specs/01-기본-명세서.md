# taketheLMO — 연구실 안전관리 통합 플랫폼 개발 명세서

## 1. 프로젝트 개요

프로젝트명: taketheLMO

프로젝트 유형: 연구실 안전관리 통합 웹 플랫폼

프로젝트 목적:
연구실의 안전관리, 연구실 정보, 안전교육, LMO 관리, 사고보고, 안전 관련 문서 등을 통합적으로 관리할 수 있는 웹 서비스를 개발한다.

단순한 정적 정보 제공 홈페이지가 아닌 실제 데이터베이스와 로그인 기능을 갖춘 Full-stack 웹 애플리케이션으로 개발한다.

향후 새로운 기능과 페이지를 지속적으로 추가할 예정이므로 확장성과 유지보수성을 최우선으로 고려한다.

## 2. 기술 스택

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- Lucide React
- Supabase PostgreSQL
- Supabase Auth
- Supabase Storage
- Vercel
- GitHub

서버 측 데이터 접근과 권한 검사를 우선 활용하며, 클라이언트에 비밀키를 노출하지 않는다.

## 3. 디자인 및 브랜드

브랜드명: taketheLMO

로고 표기: taketheLMO

영문 부제: Laboratory Safety Management Platform

한국어 서비스명: 연구실 안전관리 통합 플랫폼

디자인 방향:
- 현대적이고 전문적인 연구기관형 SaaS 디자인.
- 신뢰감 있는 짙은 녹색을 메인 컬러로 사용.
- 흰색 및 밝은 회색을 보조 컬러로 사용.
- 불필요한 장식이나 과도한 애니메이션을 지양.
- 깔끔한 카드 UI, 충분한 여백, 일관된 타이포그래피.
- 가독성과 접근성을 우선.
- PC, 태블릿, 모바일 반응형 지원.

## 4. 공통 레이아웃

모든 일반 페이지에서 동일한 Header와 Footer를 사용한다.

Header:
- 왼쪽에 taketheLMO 로고 배치.
- 중앙에 수평형 Navigation Bar 배치.
- 오른쪽에 로그인 또는 사용자 프로필 배치.
- 상단 고정형 Sticky Header.
- 메뉴에 마우스를 올리면 하위 메뉴 표시.
- 현재 접속 중인 페이지를 활성 상태로 표시.
- 모바일에서는 햄버거 메뉴로 변경.

Footer:
- 서비스명 및 서비스 소개.
- 운영기관 정보.
- 담당부서 및 문의처.
- 개인정보처리방침.
- 이용약관.
- 관련 기관 및 외부 링크.

Header, Footer, Navigation은 공통 컴포넌트로 구현한다.

## 7. 인증 및 사용자 관리

Supabase Auth를 활용해 실제 로그인 기능을 구축한다.

필수 기능:
- 이메일 및 비밀번호 로그인
- 로그아웃
- 회원가입 또는 관리자 초대
- 비밀번호 재설정
- 로그인 세션 유지
- 사용자 프로필 관리
- 로그인 상태에 따른 페이지 접근 제어

사용자 권한:
- super_admin
- safety_admin
- lab_manager
- lmo_manager
- researcher

사용자 역할에 따라 페이지 및 데이터 접근 권한을 다르게 설정한다.

관리자 페이지는 URL 접근뿐 아니라 서버 및 데이터베이스 수준에서도 권한을 검증한다.

## 8. 데이터베이스

Supabase PostgreSQL을 사용한다.

기본 테이블:
- profiles
- labs
- lab_memberships
- notices
- posts
- documents
- training_courses
- training_records
- inspection_templates
- inspection_items
- inspection_runs
- inspection_responses
- corrective_actions
- incident_reports
- lmo_facilities
- lmo_records
- attachments
- audit_logs

모든 주요 테이블은 UUID 기본키를 사용한다.

created_at, updated_at을 공통 관리한다.

사용자, 연구실, 교육, 점검, 사고, LMO 정보 간 관계를 적절하게 설정한다.

첨부파일은 Supabase Storage에 저장하고 DB에는 파일 경로 및 메타데이터를 저장한다.

RLS 정책을 적용해 사용자가 권한이 있는 데이터에만 접근하도록 한다.

관리자 권한 및 주요 안전관리 데이터의 변경 기록을 별도로 보존한다.

## 9. 보안

- Supabase Auth 인증 사용.
- Row Level Security 적용.
- 사용자별 데이터 접근 권한 분리.
- 관리자와 일반 사용자 권한 분리.
- 환경변수로 API 키 관리.
- Service Role Key는 서버 환경에서만 사용.
- 비밀번호 직접 저장 금지.
- 파일 업로드 접근권한 검사.
- 사고보고 등 민감한 정보의 접근 제한.
- 중요 관리 작업의 감사 로그 기록.

## 10. 프로젝트 폴더 구조

기능별 폴더와 공통 컴포넌트를 분리한다.

app/: 페이지 및 라우팅

components/layout/: Header, Footer, Navigation

components/ui/: 공통 UI 컴포넌트

features/: 안전관리, 연구실 관리, 교육, LMO 등 기능별 모듈

lib/: Supabase 및 인증 관련 로직

types/: TypeScript 타입

config/: 메뉴 및 권한 설정

supabase/migrations/: 데이터베이스 마이그레이션

public/: 이미지 및 로고

새로운 페이지를 추가할 때 기존 공통 레이아웃과 기능에 영향을 주지 않도록 설계한다.

## 11. 개발 및 구현 원칙

가장 중요:

1. 처음부터 모든 기능을 한 번에 구현하려 하지 않는다.
2. 우선 기본 홈페이지와 디자인 시스템을 완성한다.
3. 로그인과 Supabase DB 연결을 진행한다.
4. 각 기능을 독립적인 모듈로 개발한다.
5. 공통 컴포넌트를 적극 활용한다.
6. 반복되는 UI는 재사용 가능하도록 만든다.
7. 실제 DB에 저장되지 않는 기능을 구현 완료라고 표시하지 않는다.
8. 서버 측 권한 검사를 반드시 적용한다.
9. 모든 페이지의 디자인 일관성을 유지한다.
10. 추후 기능을 추가하기 쉬운 구조로 작성한다.

## 12. 개발 진행 순서

1단계: 프로젝트 기본 환경 구축 및 홈페이지 UI 완성.

2단계: 상단 헤더, 내비게이션, Footer, 공통 디자인 시스템 구축.

3단계: Supabase 연동 및 로그인 구현.

4단계: 사용자 프로필 및 권한 관리 구현.

5단계: 공지사항, 자료실, 연구실 관리 구현.

6단계: 안전교육, 점검, 사고보고 기능 구현.

7단계: LMO 관리 기능 구현.

8단계: 관리자 페이지 및 통계 구현.

9단계: Vercel 배포 및 전체 테스트.

## 13. 최우선 개발 요청

이번 첫 번째 개발 단계에서는 다음 항목에만 집중한다.

- Next.js 프로젝트 기본 구축.
- taketheLMO 브랜드 적용.
- 왼쪽 로고 및 상단 Navigation Bar 구현.
- 메인 홈페이지 구성.
- 공통 Header 및 Footer 구현.
- 전체 페이지에 적용할 레이아웃 구축.
- 로그인 페이지의 기본 UI 구축.
- 모바일 반응형 구현.
- 추후 페이지 추가가 쉬운 폴더 및 컴포넌트 구조 구축.

아직 완성되지 않은 기능까지 억지로 구현하지 말고, 먼저 확장 가능한 홈페이지의 기본 뼈대를 완성한다.

최종 목표는 연구실 안전관리 업무를 하나의 웹 플랫폼에서 통합적으로 처리할 수 있는 taketheLMO 서비스를 구축하는 것이다.
