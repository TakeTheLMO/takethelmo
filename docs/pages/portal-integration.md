# 포털 업무 화면 통합

- `/portal`의 상단 메뉴·SectionLayout·왼쪽 메뉴를 공통 화면으로 사용한다. `/`는 `/portal`로 연결한다.
- 계정은 기존 SQLite 계정과 세션을 그대로 사용하며 `/login`, `/signup`으로 연결한다. 기존 Supabase 기관 인증은 별도 경로로 보존한다.
- 내 업무, 신청·IBC 문의, 교육·증빙, 안전점검·사고·개선조치, LMO 확인·대장, 연구실·구성원, 자료실·검색·가이드, 알림, 관리자 사용자 관리로 연결한다.
- `/demo/*`와 `/prototype-login`은 대응하는 정식 경로로 이동한다. 저장 키·DB·첨부 원본·기존 사용자 자료는 유지한다.
- 체험 역할 전환과 전체 체험 초기화는 정식 화면에서 제공하지 않는다. 계정의 실제 역할로 처리하며 admin만 사용자 관리·타인 자료를 조회한다.
- 새 계정에는 업무 예제를 만들지 않는다. 기존 미수정 초기 예제만 제외하고 실제 작성/수정 자료와 첨부는 보존한다. 별도로 넣은 `[예시]` 계정은 라벨과 내용을 유지한다.
- AI 미연결·공식 기관 서식/신고 미연동 상태는 정직하게 표시한다. UI를 옮기는 것만으로 운영 보안·법적 심의·AI가 완성됐다고 표현하지 않는다.

## 확인된 동작과 범위

- 도메인 컴포넌트의 초안 저장·네 확인 응답 사본·IBC 문의 상태·대장 세 수량/단위/정정 이력을 기존 SQLite 인증/동기화와 통합했다. 저장 형식과 계정별 브라우저 키는 기존 v1을 유지한다.
- 본인 기록은 서버에서 상태·처리 이력을 확인한다. 검토/승인/반려·답변 완료는 admin의 사용자 관리 화면에서 처리한다. 기존 업무 기록 삭제와 과거 처리 이력 변경은 거부한다.
- 교육과정은 사용자가 추가한 뒤 이수증을 등록한다. 연구실 이름·위치·코드·설명도 실제 입력을 사용한다. 공식 시설 등급/신고·허가 완료를 임의로 표시하지 않는다.
- 기존 Supabase 기관 공지·관리 기능은 기관 로그인 경로를 보존했다. SQLite 계정과 기관 SSO를 통합했다고 표현하지 않는다. MSDS/영상 등 자료가 없는 범주는 빈 상태다.
- 검증 자료: `output/playwright/portal-public.png`, `portal-mobile.png`, `user-management.png`. 기존 DB를 `data/*.before-portal-*.sqlite`에 백업 후 이관했다.
