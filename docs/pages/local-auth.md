# 포털 로컬 계정

- 경로: `/login`, `/signup`. `/prototype-login`은 이전 주소이며 이동 처리한다. SQLite 계정은 Supabase 기관 계정과 별개다.
- 관리자: 아이디 `admin`, 비밀번호 `admin`, 역할 `super_admin`. 최초 인증 저장소 초기화 시 생성하고 기존 계정·비밀번호·활성 상태를 덮어쓰지 않는다. 비밀번호는 salt/scrypt 해시로 저장한다.
- 로그인은 아이디 또는 이메일을 받는다. 신규 회원은 이름·이메일·비밀번호·역할을 입력한다. 일반 가입 비밀번호 기준은 8~128자를 유지한다.
- 가입 역할: 일반 연구원, 연구실 안전담당자, LMO 담당자, 기관 안전관리자. 시스템 관리자는 공개 가입과 일반 계정의 신규 역할 부여에서 제외한다. 기존 `super_admin` 계정도 실제 admin 아이디가 아니면 타인 자료 관리 권한이 없다.
- 가입 정보는 DB·로그인·세션·상단 표시와 연동한다. 포털에는 체험 역할 전환과 전체 초기화가 없으며, 계정의 실제 업무 역할을 적용한다. 역할 이름과 별도로 활성 admin 아이디를 페이지·API·DB 접근 함수에서 확인한다.
- `sample.*@example.test`는 예시 데이터 전용으로 예약한다. 가입자가 이 주소로 예시 계정 경로를 사용할 수 없다.
- 구 DB에는 컬럼을 추가하며 기존 계정의 역할을 보존한다. 직책 선택은 역할과 중복되어 제거했으며 구 DB 컬럼은 호환성을 위해 보관한다. 기존 비밀번호·ID·세션·계정별 기록은 유지한다.
- 역할은 현재 포털의 계정별 작성 권한이다. 기관의 임명·지정 책임자·법적 권한을 증명하지 않는다. 비활성 계정은 세션을 무효화하고 데이터는 보존한다.
- 검증: 관리자 로그인·세션·중복 생성 방지, 가입 정보 검증/복원, 기존 DB 보존, 브라우저 가입·로그아웃·재로그인·계정 분리.
