# 페이지 명세: 사용자 체험 데모

## 1. 기본 정보
- 경로: `/demo`, `/demo/[section]`. 홈은 데모로 이동, 기존 홈은 `/portal` 보존.
- 모듈: `features/demo/`. 원격 `demo` 브랜치 기반 로컬 작업.
- 로드맵: 4~10단계 및 검토 기능의 프론트엔드 체험. 운영 구현 완료를 뜻하지 않음.

## 2. 목적 및 범위
사용자 요청에 따라 가상 데이터로 다음 15개 기능을 연결한다. 검토 단계 기능도 포함한다.
1. 자료 근거를 연결하는 안전 챗봇(로컬 규칙 기반 데모)
2. 문서·교육·서식 통합 검색
3. 상황별 단계 가이드와 진행 저장
4. LMO 해당 여부 확인 지원 질문 및 확인 목록
5. 개인 안전 현황과 할 일
6. 기한·처리 상태 알림, 읽음 처리
7. 교육 신청·이수증 파일 등록 및 이력
8. SOP·서식 자료실, 개정 이력·즐겨찾기·예제 다운로드
9. 긴급 안내와 실제 기관 연락처 확인 경로
10. 점검 입력·지적사항·증빙·개선조치·검토 종결
11. 사고·아차사고 접수 및 후속 조치
12. 신청·검토 시작·보완 요청·재제출·승인·반려와 이력
13. 연구실·시설·구성원·관리대장
14. 연구원/연구실 담당자/LMO 담당자/안전관리자/시스템 관리자 역할 체험
15. 모바일 반응형 메뉴·폼·목록

## 3. 접근 권한
- 공개 가상 시나리오이며 로그인과 별개로 데모 역할을 전환한다.
- 연구원은 본인 신청·보고서·교육 현황, 담당자는 데모 연구실, 관리자는 데모 기관 범위를 본다.
- 자기 신청 검토 금지. 연구실 담당자는 일반 신청, LMO 담당자는 LMO 신청, 안전관리자는 전체 검토.
- 데모의 역할 검사는 UX 체험용이며 보안 경계가 아니다. 기존 실제 인증·관리자·RLS는 변경하지 않는다.

## 4. 구성
좌측 메뉴, 검색, 역할 선택, 알림, 고정 데모 표시, 개인 대시보드. 모바일 메뉴 접기.
빈 검색/빈 목록 안내, 필수 입력 검증, 저장 오류 피드백, 제출 및 상태 변경 결과를 표시한다.

## 5. 데이터
기관·사람·기록은 가상. localStorage 버전 키로 저장, 실제 업로드 파일은 IndexedDB(5MB 이하 PDF/PNG/JPEG).
파일은 서버로 전송하지 않는다. 데모 초기화는 확인 후 브라우저 내 데모 데이터만 초기화한다.
공식 시스템은 사용자가 제공한 링크를 제공. 법령 원문·연락처·실제 이수/신고 완료를 위조하지 않는다.

## 6. 상태와 이력
신청: 제출 → 검토 중 → 보완 요청 → 재제출(제출) / 승인 / 반려. 종결 상태 재검토 불가.
개선: 조치 중 → 검토 대기 → 종결 또는 재조치 요청. 증빙 및 검토 의견 기록.
사고: 접수 → 확인 중 → 종결, 처리 의견 필수.
모든 전이는 현재 데모 역할·상태·필수 입력을 검증하고 처리자/시각/의견을 남긴다.

## 7. 예외 처리
손상되거나 미지원 버전의 저장 데이터는 안내 후 초기 시나리오를 표시하되 저장을 잠가 원본 덮어쓰기를 막는다. 사용자가 명시적으로 초기화하면 원본 문자열을 복구 키에 보관하고 초기화한다. 저장 실패는 알리고 성공으로 표시하지 않는다.
파일 저장 실패 시 기록을 만들지 않는다. 첨부 원본을 찾을 수 없으면 재등록 안내.

## 8. 완료 기준
lint, typecheck, unit, build, 기존 인증 E2E 및 주요 데모 흐름 E2E 통과. 데스크톱·모바일 확인.

## 9. 제외
실제 LLM/RAG, 법적 판정, 공식 신고·교육 연동, 서버 저장/전송, 운영 권한 보안, 이메일·푸시 발송.
사용자의 이번 요청으로 허위 데이터를 운영처럼 표시하지 않는 명시적 데모에 한해 가상 데이터 및 다기능 구현을 허용한다.

## 10. 인터뷰·수정안 반영 (2026-11-17)
- 근거: 인터뷰 상세정리, 서류작성안내 수정안(11/14), IBC 사전문의 제안, 우선반영 피드백사항(11/16), 사용자 대화. 문서 검토 의견을 실제 설문 응답이나 사용자 시험 결과로 표기하지 않는다.
- 관리대장: 모든 역할이 항목별 안내와 분리된 두 작성 예시를 읽는다. 신규 기록은 취득 경로·일자·물질명·입고량·사용량·보관량·단위(vial/tube/plate/마리/ml)·비고를 저장하며 목록·CSV에도 유지한다. 0과 미기재를 구분하며 배양 증가를 등식 검사로 막지 않는다. 기존 단일 수량은 별도 열에 보존한다.
- 서식: 핵심 작성 연습만 제공하며 16개 항목 전체 법정 서식은 구현하지 않는다. 나머지 항목의 확인 안내, 공식 안내 링크, 수입신고 준비 항목을 제공한다. 동일 단위·용량 병기는 팀 제안으로, 기관 서식·기본 단위·담당자·서명·입력 권한은 확인 필요로 표시한다. 기관 서식 파일·실제 연락처·처리 기한은 만들지 않는다.
- 문의: `IBC 사전 문의` 유형과 5개 구조화 항목, 시작 시기 미정, 신고 여부 3택 및 선택 신고정보. 신규 신청·문의 초안을 역할·유형별로 브라우저에 즉시 자동 저장하고 새로고침·화면 이동 후 복원한다. 제출 성공 시 해당 초안만 함께 제거한다. 저장 실패 시 실패 안내를 표시한다.

- 문의 상태: 접수 → 답변 준비 중 → 추가 정보 요청 → 추가 정보 제출(접수) → 답변 준비 중 → 답변 완료. 승인·반려와 혼합하지 않는다. 시작·처리·추가 정보 제출 모두 현재 역할/상태와 내용을 확인한다.
- 데모 문의 수신·답변: LMO 담당자, 기관 안전관리자, 시스템 관리자. 자기 문의 답변 및 연구실 안전담당자의 타인 문의 조회·답변은 허용하지 않는다. 이는 실제 기관 배정이 아닌 체험용 역할이다.
- 문의 알림과 대기 수는 공통 조건에서 파생한다. 추가 정보 요청은 작성자의 할 일이며 담당자의 답변 대기에서 제외한다. 답변은 본문 위에 노출하고 처리 이력에 남긴다. 접수·답변 완료가 IBC 승인/실험 시작 허가가 아니라는 안내를 폼·상세·완료에 표시한다.
- 확인 지원: 동물 투여 질문 추가. 네 질문을 ID 기준으로 확인하고 저장·복원·다운로드한다. 예/모르겠어요에 문의를 강조하고 아니요에도 진입을 제공한다. 기존 시설 변경 요청은 별도 유지한다.
- 저장: v2 키로 분리. v2가 없으면 v1을 읽어 다른 모든 값을 그대로 보존하고 다음 저장부터 v2에 쓴다. v1 원본은 유지한다. 구 버전 탭은 v1, 새 버전은 v2를 사용하므로 두 버전의 이후 수정은 병합되지 않는다. 데모 초기화는 활성 v2 데이터에 적용된다.
- 범위 밖: 실제 담당자 전송/메일, 기관 양식 확보, 운영 DB·인증·RLS 변경, 실제 IBC 심의·신고, 법적 판정, 물질 공유 검색, 전체 일상 점검 확장, 자동 기한 확정.

## 11. 작성 연속성과 대장 정정 (2026-11-17 추가 요청)
- 문의 초안에는 LMO 확인 지원의 네 응답 사본을 연결한다. 기존 제목·개요·입력 항목은 유지한다. 확인 결과로 물질 특성이나 신고 여부를 자동 추론하지 않는다. 제출된 사본은 이후 확인 지원 응답 변경과 분리한다.
- 대장 정정은 LMO 담당자·관리자만 가능하다. 새 형식과 기존 단일 수량 형식을 유지하며 원 작성자·저장 시각도 보존한다. 정정 사유·정정자·시각·수정 전후 전체 값을 누적 보관한다. 모든 역할이 이력을 볼 수 있다.
- 수량 검증과 정정 사유 입력은 저장 시 다시 검사한다. 편집 시작 후 다른 변경이 생기면 오래된 편집 내용으로 덮어쓰지 않고 다시 열도록 안내한다.
- 초안·이력은 동일 브라우저의 데모 저장소에만 보관된다. 데모 초기화 시 함께 초기화되며 운영용 서버 감사로그나 기관 공식 전자기록은 아니다.
