# 프로토타입 사용자·등록 자료 관리

## 최신 검토 — 2026-11-17 PPT·계정 요구사항

- 일상점검은 전용 편집 화면에서 항목별 결과·조치사항·미해당 사유를 정정하고, 별도 동작으로 포털 관리자 확인을 남긴다. 원본 점검 내용과 확인 대상 이력 번호를 보존하며 내용 변경 시 재확인이 필요하다.
- 관리자 답변·확인·정정은 사용자 알림에 연결된다. 관리자 포털은 비관리자 계정들의 미종결 조치·사고를 집계한다.
- 공개 가입에는 네 가지 업무 역할만 제공한다. 기존 `super_admin` 역할 계정은 보존하지만 실제 관리 권한은 활성 `admin` 아이디에만 부여한다. 시스템 관리자 역할을 새로 부여할 수 없다.
- 관리자 편집 도중 다른 자료만 변경되면 대상 원본이 동일한 경우에 한해 저장한다. 대상이 바뀌었거나 저장 직전 계정 버전이 다시 바뀌면 409로 거부한다. 원본 없는 기존 첨부의 단순 정정은 허용하지만 신규 검토 제출·완료에는 본인 원본을 확인한다.
- 단위 84개·브라우저 30개 전체 통과, build·타입 검사 통과, lint 오류 0/기존 경고 3. 아래 검증 숫자와 `/demo/users` 설명은 이전 구현 이력이다. 현재 주소는 `/management/users`다.
- [요구사항 전체와 남은 범위](../2026-11-17-requirements-review.md), [일상점검](daily-inspections.md).

## 2026-11-17 관리자 통합 확장

- `/management/users`: 사용자·카테고리·상태·첨부 여부 필터, 분류별 건수, 해당 자료를 바로 여는 참조 링크. 연구실 정보·교육과정·LMO 확인 응답도 조회·정정 대상에 포함한다.
- `/management/menus`: 전체 일반 메뉴를 기준으로 관련 사용자 자료를 모으고, 실제 페이지를 열거나 해당 자료를 수정한다. 페이지 제목·설명·안내 본문과 공지·문서·서식·링크·첨부를 작성/게시/보관한다.
- 공개된 공통 콘텐츠는 해당 메뉴와 통합 검색에서 조회한다. 미게시/보관 콘텐츠와 변경 이력은 admin 전용이다. 공통 첨부는 게시된 콘텐츠에 연결된 경우에만 로그인 사용자에게 제공한다.
- SQLite 계정의 서버 가드와 DB 접근 계층에서 admin 아이디·활성을 확인한다. 변경 사유와 이전/이후 값, 버전 검사를 적용하고 하드 삭제하지 않는다. 기존 Supabase 영역은 별도 권한 체계를 보존한다.
- 검증: 사용자 카테고리/첨부 연결, 실제 수정·이력·충돌·비관리자 차단, 메뉴별 게시·수정·보관·첨부 노출, 일반 사용자 화면 반영 및 모바일 화면.
- 결과: 단위 63개 통과, 최종 공통 콘텐츠 단위 4개 재검증. 브라우저 25개 중 저장 후 갱신 순서 1건을 수정하고 관리자 관련 5개 재실행 모두 통과. 최종 build·타입 검사 통과, lint 오류 0/기존 경고 3. 화면: `output/playwright/admin-users-live.png`, `admin-menus-live.png`, `menu-management-mobile.png`.
- 사이트 기능 자체의 권한/법적 판정/외부 연계 설정은 이 화면에서 임의로 변경하지 않는다. 안내·게시 자료와 현재 구현된 사용자 업무 기록을 관리하는 범위이며, 고정된 기본 참고 예제는 원래 라벨을 유지한다.

- `/demo/users`: SQLite의 admin 아이디 계정만 이용. 서버 페이지·API·데이터 접근 함수에서 세션과 관리자 여부를 확인한다. Supabase 운영 관리자와 분리한다.
- 이름·이메일·역할 검색, 사용자 상세와 계정 수정(이름·이메일·역할·활성 상태·관리자 메모). 비밀번호·세션 토큰은 조회하지 않는다.
- 사용자 등록 내용은 계정별 서버 스냅샷에 저장한다. 신청·교육/이수증·사고·점검·개선조치·대장·구성원 중 추가/변경한 자료만 집계하며 초기 예제는 등록 자료로 표시하지 않는다.
- 첨부는 서버에 원본을 저장하며 본인 또는 admin만 내려받는다. 기존 브라우저 원본은 사용자가 로그인한 상태에서 서버로 이전한다. 원본이 없으면 확인 필요로 표시한다.
- 관리자 자료 수정은 사유 필수. 수정 전후 값·처리자·시각을 DB에 보존한다. 계정 변경은 기존 세션에도 반영된다. 비활성화하면 해당 계정 세션을 만료한다.
- 사용자 저장·첨부 등록은 관리자 알림에 연결하며 읽음 처리와 사용자/자료 링크를 제공한다. 비관리자에게 관리자 알림·타인 자료를 공개하지 않는다.
- 스냅샷 수정에는 버전 검사를 적용한다. 오래된 내용의 덮어쓰기를 막고 충돌한 브라우저 입력은 별도 복구 사본으로 보관한다. 서버 저장 실패는 실패 상태와 재시도 버튼을 표시한다.
- SQLite 서버 저장을 사용하는 프로토타입이다. 기존 Supabase 권한/RLS·법정 업무 완료 여부와 분리한다.
