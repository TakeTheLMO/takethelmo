| LMO 확인 지원 | 동물 투여 질문, 모든 응답에서 사전 문의 진입 | 예·아니요·모르겠어요 각각 확인 |

## 핵심 처리 원칙

- 문의 접수·답변 완료는 IBC 승인이나 실험 시작 허가가 아닙니다. 폼·상세·답변 완료 화면에서 안내합니다.
- 문의 수신 역할은 데모에서 LMO 담당자와 기관·시스템 관리자로 정했습니다. 실제 기관 수신자와 처리 기한은 확인이 필요합니다. 본인 문의에는 답변할 수 없습니다.
- 문의 답변 대기와 작성자의 추가 정보 제출 할 일을 구분합니다. 추가 정보 제출 후 접수로 돌아가 다시 답변을 준비합니다.
- 신규 신청·문의 초안은 역할·유형별로 브라우저에 자동 저장하며 화면 이동·새로고침 후 복원합니다. 제출 성공 시 해당 초안만 지웁니다. 저장 실패는 화면에 알립니다.
- 확인 지원에서 문의 작성으로 이동하면 네 응답 사본을 연결합니다. 기존 작성 내용은 유지하고 제출 후 확인 지원의 응답을 바꾸어도 문의의 사본은 유지합니다.
- 관리대장의 기록 정정과 정정 이력을 추가했습니다. 수정 전후 값·사유·작성자·시각을 남기며, 기존 단일 수량을 신규 수량 항목으로 임의 변환하지 않습니다. CSV에는 정정된 현재 값이 나옵니다.
- 신규 대장은 단위를 함께 저장하고 0과 미기재를 구분합니다. 배양 등으로 입고량과 보관량이 달라도 자동 오류 처리하지 않습니다.
- 기존 단일 수량 기록은 원형으로 보존하고 CSV에도 별도 열로 내보냅니다. 예시 데이터는 실제 관리기록에 자동 삽입하지 않습니다.
- 수입 물질 명칭 안내에는 수입 조건을 붙였습니다. 동일 단위·용기당 용량 병기는 팀 제안입니다. 분양·자체 제작 명칭, 기관 서식·기본 단위·서명·작성 권한은 확인 필요로 표시합니다.

## 저장과 호환성

- 저장 키를 `takethelmo:frontend-demo:v2`로 분리했습니다. v2가 없으면 v1을 읽고 다음 변경부터 v2에 저장하며 v1 원본은 남깁니다.
- v1 시드 원본 코드에서 만든 테스트 자료로 기존 신청·대장·3개 답변이 그대로 유지되는지 확인했습니다. 실제 사용자 브라우저 데이터의 사본이라고 표현하지 않습니다.
- v1을 사용하는 구 버전 탭과 v2를 사용하는 새 버전 탭의 후속 수정은 서로 병합하지 않습니다.
- 손상된 저장 값을 읽으면 원본 보호를 위해 저장을 막습니다. 명시적인 초기화 시 손상 원문을 복구 키에 먼저 보관합니다.
